# 两分支维护约定（SDL4 / SDL5）

> 本仓库有两个长期并行的分支，功能一致、仅连接层不同。改 bug 时先分清落在哪一层。

## 分支关系

| 分支 | SDL 底座 | 连接入口 | targetSdk |
|---|---|---|---|
| `main` | sdl_android 5.8.0 | `SdlManager` | 35 |
| `legacy/sdl4` | sdl_android 4.12.2 | `SdlProxyALM` + `IProxyListenerALM` | 32 |

两个分支的**功能**（歌词 / 导航 / 渲染 / ETA / 软键 / 计时器 / 架构）完全一致，
只有连接层不同。这已通过 2026-11-22 的 diff 验证（11 个核心非连接层文件两分支内容一致）。

## 文件分层

### 非连接层（两分支内容一致，可 cherry-pick 互通）

```
core/SyncPlayCore.java
SyncGlanceApp.java
display/StateRenderer.java  ClockInstruction  ConnectionStatus  ScreenFrame  ScreenPreviewView  Glyphs
lyric/*（LyricManager Lrc NeteaseLyric Romaji SyncLyric TitleNorm）
nav/*（AmapLinkClient LinkEnvelope）
model/*（NowPlaying Navigation）
service/CommandRouter  NotificationCatcher  KeyMap
activity/MainActivity  LogActivity
util/Log2  Kana
res/  app/src/test/  docs/
```

这些文件**不 import 任何连接层类**（`SyncPlayCore` 只依赖 `StateRenderer` + 数据层，
`StateRenderer` 只依赖自己定义的 `Sender` 接口），所以两边可以完全共用。

### 连接层（SDL 版本不同，不能互通，改 bug 要两边分别改）

```
service/SdlService.java        ← SdlProxyALM vs SdlManager，骨架不同
receiver/SdlReceiver.java      ← 4.x vs 5.x 行为不同
receiver/BootReceiver.java     ← 4.x vs 5.x 行为不同
receiver/SyncRouterService.java（4.x）/ SdlRouterService.java（5.x）  ← 类名不同
AndroidManifest.xml            ← targetSdk / foregroundServiceType 等不同
app/build.gradle.kts           ← sdl 版本 / targetSdk 不同
```

## 维护约定

### 改非连接层的 bug（如 SyncPlayCore、StateRenderer、歌词、导航）

```bash
# 1. 在 main 改并提交
git checkout main
git add app/src/main/java/com/xigaigai/syncglance/core/SyncPlayCore.java
git commit -m "fix: xxx"

# 2. cherry-pick 到 legacy/sdl4（文件内容一致 → 零冲突）
git checkout legacy/sdl4
git cherry-pick <上面 commit 的 hash>
git checkout main
```

### 改连接层的 bug（如 SdlService 的连接/收尾逻辑）

两边的 `SdlService` 骨架不同（`SdlProxyALM` vs `SdlManager`），
同一个逻辑要分别在两边改。

**但注意**：显示逻辑的大头其实不在 `SdlService` 里 ——
计时器两步法在 `StateRenderer.timerRpcList()`、时钟刷新在 `SyncPlayCore`、
软键文案在 `StateRenderer.getSoftKeyTexts()`。这些都是非连接层，
所以**大部分 bug 都能在非连接层修掉、cherry-pick 同步**；
只有真正落在「建连 / 断连 / 收发时序」的 bug，才需要两边分别改。

## 边界提醒

1. **SdlService 是「连接 + 显示」混合体**，但显示逻辑已逐步下沉到
   `StateRenderer` / `SyncPlayCore`，`SdlService` 只剩转发和连接收尾。
2. **cherry-pick 前先确认 commit 只碰非连接层文件** —— 可以用
   `git show --stat <hash>` 看它改了哪些文件，混入连接层文件就要手动拆。
3. **不要用 `git checkout main -- <连接层文件>` 同步连接层** —— 那会把
   `SdlManager` 代码盖到 4.x 分支上，直接编译失败。
4. 两个分支的**文档**（docs/）尽量也保持同步，避免认知漂移。

## 已知差异（有意为之）

| 项 | main | legacy/sdl4 | 原因 |
|---|---|---|---|
| APP_ID | 1397139053 | 1397139052 | 两版并存时 Multiplex 通道去重不冲突 |
| 受控重试参数 | 2s × 4 = 8 秒 | 无（4.x TransportBroker 自己等） | 5.x 秒失败后重试，按福特 SYNC 1.1 车机响应速度留余量，4.x 不需要 |
| FLAG_MULTI_SECURITY_OFF | 显式传 | 不适用（4.x 无此 flag） | 见 docs/连接可靠性排查.md |
| autoActivateID | 无（5.x 删了） | `setAutoActivateID` | 4.x 有、5.x 删了整套能力 |
| 前台服务 + 连接状态通知 | **无**（2026-11-22 移除） | 有（4.x 版仍是前台服务 + 通知） | 见 `docs/通知移除与存活权衡.md`；**这条改动暂时只在 main 上做**，若日后回退到 4.x 分支需同样处理 |
