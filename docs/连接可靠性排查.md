# 连接可靠性排查（2026-11-21 实车测试）

> 本文是「车机连不上 / 重连超时」问题的排查记录。
> **上下文压缩后从这里恢复**：结论、已排除项、下一步都在下面。

---

## 一、三个现象

1. 连上蓝牙后，车机应用列表里没有 SyncPlay；必须人工「查找移动应用」
2. 只有「在查找的同时启动 App」才能发现
3. 已连接后下车锁门再上车：车机显示「正在连接 SyncPlay」→ 最终超时失败

---

## 二、已确认的事实（都有日志证据）

### 2.1 Router 只有 20 秒窗口

实车观察：

- 连上蓝牙后**立刻**出现一条 SDL 的通知，右上角带 **20 秒倒计时**，内容 `waiting for connection`
- 在这 20 秒内于车机上「查找移动应用」→ 通知变 `Connected to SYNC`
  → SyncPlay 通知出现（已连接/正在注册）→ 车机进入欢迎页 ✅
- 20 秒过后 Router 退到后台，之后车机再连就失败

**这就是现象 1 的根因**：车机需要人工触发查找，而窗口只有 20 秒。

### 2.2 Router 的上下线次数严重不对称

```
上线（onCreate/onStartCommand 发的 ALIVE）：20+ 次
下线（onDestroy 发的 DEAD）：只有 4 次
```

大部分 Router 实例退出时**没走 `onDestroy`** —— 是退到后台后被系统静默回收的。

### 2.3 失败的确切形态（关键）

```
13:58:51.808  [Boot] ACL_CONNECTED
13:58:51.827  [SYNC] SyncPlay 服务创建
13:58:51.874  [SYNC] 连接结束（CONNECTING）    ← 47ms 后失败
13:58:51.890  [SYNC] 服务销毁
13:58:51.902  [Router] RouterService 上线      ← Router 起来了
13:58:55.086  [SdlReceiver] onSdlEnabled       ← 车机连上 Router
13:58:55.110  [SYNC] SyncPlay 服务创建
13:58:55.134  [SYNC] 连接结束（CONNECTING）    ← 24ms 后失败
13:58:55.159  [SYNC] 服务销毁
```

**注意：Router 明明在上线后 3~4 秒，SdlManager 仍然绑不上它。**

### 2.4 失败时 Router 根本没收到请求

`SyncRouterService` 在 `onCreate`/`onStartCommand` 都会发 ALIVE 广播。对比：

| 时刻 | 有新的 ALIVE 吗 |
|---|---|
| ✅ 成功 13:57:30.517 服务创建 | **有**（13:57:30.540 又来一次） |
| ❌ 失败 13:58:55.110 服务创建 | **没有** |

说明 SdlManager 的绑定请求**压根没到达 RouterService**（连 `onStartCommand` 都没触发），
所以在 13~24 毫秒内就判定失败 —— 这不是超时，是**发起前就认定「Router 不可用」**。

### 2.5 成功那次的唯一区别：Router 是"新鲜唤醒"的

```
13:57:27.375  [Router] 上线
13:57:27.545  [Router] 上线
13:57:30.507  onSdlEnabled
13:57:30.517  服务创建
13:57:30.540  [Router] 上线          ← 服务起来后 23ms 又被唤醒一次
13:57:33.867  OnHMIStatus CONNECTING → NONE
13:57:34.002  → BACKGROUND
13:57:35.276  → LIMITED
13:57:35.724  → FULL                 ← 成功
```

**结论：只有"刚启动/刚被唤醒"的 Router 才能被 SdlManager 绑定；退到后台的 Router
虽然进程还在，但对 SdlManager 已经不可用。**

## 三、已排除的假设

| 假设 | 为什么排除 |
|---|---|
| 服务没被拉起 | 已修 `onSdlEnabled` 两条路都走（`81c0b3c`），日志确认 `服务创建` 出现了 |
| Router 没被拉起 | Router 确实上线了（2.3） |
| 系统后台限制 | `am get-standby-bucket` = 10（ACTIVE，最好分桶） |
| 蓝牙广播没送达 | 每次 `ACL_CONNECTED` / `ACL_DISCONNECTED` 都收到了 |
| PendingIntent 单独失效 | 已改成两条路都走，且日志显示服务确实起来了 |

## 四、未验证（缺证据）

1. **SDL 库内部为什么判定「Router 不可用」** —— 需要 `logcat` 里 `tag: SDL` /
   `Sdl Broadcast Receiver` 的日志，但**车里没法连 adb**，抓不到
2. 车机为什么长时间只给 `NONE` —— 13:57 那次到了 `FULL`，说明车机本身支持；
   可能只是需要用户从车机菜单确认

## 五、下一步方案（未实施）

**让 `SyncRouterService` 常驻前台**（在 `onCreate` 里主动 `startForeground`）。

理由：

1. Router 退到后台后 SdlManager 绑不上（2.4 / 2.5）
2. 20 秒窗口对"人工查找移动应用"这个操作方式太短（2.1）

代价：多一条常驻通知（Router 在独立进程，无法与 `SdlService` 通知合并）。

与「连接生命周期跟官方一致」的原则冲突，但符合该原则的例外条款
（官方策略在本车实测跑不通）。

**候选的补充方案**：SdlManager 快速失败（< 3 秒且从未收到 OnHMIStatus）后
延迟 1.5 秒重试 2~3 次，再走 stopSelf。治标，但能覆盖"Router 正在被唤醒"的短窗口。

## 六、顺带确认的正面结论

- **软键 9003「计时」的三态循环在车机上跑通**（13:54:55 开始 → 13:55:00 暂停 → 13:55:03 清零）
- 连接成功时能一路到 `FULL`，`Show` / `SetMediaClockTimer` / 软键都正常
